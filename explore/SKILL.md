# Explore — Parallel Codebase Investigation

Explore codebases and answer questions fast by deploying parallel agents and caching structural blueprints for repeat visits.

## When to Use

- Answering questions about how a codebase works
- Understanding architecture, data flow, or design decisions
- Investigating unfamiliar packages or modules
- Onboarding to a new project
- Any question that requires reading across multiple areas of a codebase

## Phase 1: Check for Blueprints

Before exploring, check if a blueprint already exists:

```
<package-root>/.claude/blueprint.md
```

If found, **read it first** — it contains the structural map from a prior exploration and will drastically reduce the search space. Feed relevant sections to agents in their prompts so they skip re-discovery.

If no blueprint exists, agents will create one as a side effect of exploration (see Phase 3).

## Phase 2: Parallel Exploration

Deploy **2–4 Explore agents in a single message** to investigate in parallel. Each agent gets a distinct focus area.

### Agent Assignment Strategy

Split the question into orthogonal search dimensions. Common splits:

| Pattern | Agent 1 | Agent 2 | Agent 3 |
|---------|---------|---------|---------|
| "How does X work?" | Entry points & API surface | Core logic & data flow | Config, types & edge cases |
| "Where is X?" | Grep for identifiers | Glob for file patterns | Trace imports/exports |
| Architecture overview | Frontend/client | Backend/API | Shared/infra |
| Data flow question | Producer/writer | Consumer/reader | Schema & validation |

### Agent Prompt Template

Each agent's prompt must include:

1. **The user's question** — verbatim
2. **Focus area** — what this specific agent should investigate
3. **Blueprint context** — relevant sections from an existing blueprint (if available)
4. **Output requirements:**
   - Answer their focus area concisely
   - List every file they read (path + 1-line purpose)
   - Note key functions, types, and patterns discovered
   - Flag anything surprising or worth investigating further

```
Agent(
  subagent_type: "Explore",
  run_in_background: true,
  description: "<focus-area> explorer",
  prompt: <prompt with question, focus, blueprint context, output requirements>
)
```

Launch all agents in a **single message** for true parallelism.

## Phase 3: Blueprint Generation

After agents return, update or create the blueprint at `<package-root>/.claude/blueprint.md`.

### Blueprint Format

```markdown
# Blueprint: <package-name>
<!-- Auto-generated by /explore. Last updated: YYYY-MM-DD -->

## Structure
<top-level directory map with 1-line descriptions>

## Key Entry Points
<main files, exports, CLI commands, route handlers>

## Architecture
<how the major pieces connect — data flow, layering, key abstractions>

## Patterns & Conventions
<naming conventions, file organization, shared utilities, error handling>

## Key Files
| File | Purpose |
|------|---------|
| path/to/file.ts | Brief description |
| ... | ... |
```

### Blueprint Rules

- **Append, don't overwrite** — if a blueprint exists, merge new discoveries into it
- **Keep it structural** — blueprints describe *what's where*, not *how to use it*
- **Cap at ~150 lines** — if it grows beyond that, trim less-important entries
- **One blueprint per package** — in a monorepo, each package gets its own blueprint in its `.claude/` directory

## Phase 4: Synthesize & Answer

Combine agent results into a single answer:

1. **Direct answer** — address the user's question clearly
2. **Supporting evidence** — reference specific files, functions, and line numbers
3. **Architecture insight** — connect the dots between what different agents found
4. **Further exploration** — suggest follow-up questions if the topic is deep

Keep the answer educational — explain the "why" behind design decisions when evident.

## Quick Reference

| Step | Action |
|------|--------|
| 1 | Check for existing blueprint at `<pkg>/.claude/blueprint.md` |
| 2 | Deploy 2–4 Explore agents in parallel with distinct focus areas |
| 3 | Wait for agents, then update/create the blueprint |
| 4 | Synthesize findings into a clear answer |

## Important Notes

- Always launch agents in a **single message** for true parallelism
- Feed existing blueprint context to agents so they skip known ground
- Blueprints are **structural caches**, not documentation — keep them lean
- In monorepos, identify the right package root before checking for blueprints
- If a blueprint is stale (files referenced no longer exist), prune it during the update
